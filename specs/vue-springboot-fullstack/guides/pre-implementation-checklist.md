# 编码前检查清单

> 在写第一行代码前先回答这 5 组问题。**未通过不许动键盘**。

## 1. 我究竟要做什么？

- [ ] 用一句话能说清这个改动的**业务意图**（不是技术动作）
- [ ] 写出**输入 / 输出 / 副作用**：
  - 输入是什么？来自前端表单 / 上游接口 / 定时任务？
  - 输出给谁消费？前端列表 / 报表 / 第三方？
  - 是否有副作用？写库、发消息、调外部 API？
- [ ] 是否有"看似简单实则复杂"的隐含需求？（如分页、排序、权限隔离、多租户）

> 拿不准就先问产品/后端，**不要靠猜**。

---

## 2. 这个改动落在哪一层？

| 改动                       | 主要落点          |
| -------------------------- | ----------------- |
| 新增表单页                 | 前端 Page + Composable |
| 新增列表/表格              | 前端 Page + Pinia + axios |
| 新接口                     | 后端 Controller + Service + Mapper |
| 新业务规则                 | 后端 Service（**不是** Controller） |
| 新表 / 加字段              | Flyway 迁移 + Entity + Mapper + DTO/VO + 前端类型 |
| 新权限                     | Security 配置 + `@PreAuthorize` + 前端路由 meta |
| 跨模块查询/聚合            | 通常需要新 Service 或领域服务，而不是让 Controller 横跨多 Service |

- [ ] 我的改动是否**只动了它该动的层**？
- [ ] 是否在 Controller 里写了业务逻辑？（应放 Service）
- [ ] 是否在 Service 里写了 SQL？（应放 Mapper）
- [ ] 是否在 Vue 模板里塞了复杂表达式？（应抽 computed）

---

## 3. 数据契约是否对齐？

- [ ] 后端 DTO/VO 是否加了 `@Schema`？
- [ ] 前端是否跑过 `pnpm gen:api` 同步类型？
- [ ] 时间字段是否是 ISO 8601 字符串？
- [ ] Long ID 是否序列化为字符串？
- [ ] 错误码是否在 `ErrorCode` 枚举里登记？
- [ ] 分页字段是否符合 `records/total/page/size/pages`？

> 详见 [shared/api-contract.md](../shared/api-contract.md) 与 [shared/types-sync.md](../shared/types-sync.md)。

---

## 4. 失败路径有没有想清楚？

- [ ] 网络失败：前端是否有 loading / 错误提示？
- [ ] 401 / 403：是否触发 refresh / 跳登录？
- [ ] 后端依赖（DB / Redis / 外部）失败：是否有降级或友好报错？
- [ ] 并发：是否会重复扣库存 / 重复创建？是否需要乐观锁或幂等键？
- [ ] 校验失败：错误信息能否告诉用户**具体哪个字段错了**？
- [ ] 大数据量：列表是否分页？批量操作是否有上限？

---

## 5. 安全 & 权限

- [ ] 这个接口/页面**默认对谁开放**？登录用户？特定角色？
- [ ] 用户能否看到/操作**别人的数据**？（多租户/数据隔离）
- [ ] 用户输入是否有 XSS / 注入风险？
- [ ] 是否要写入日志的字段含 PII？是否已脱敏？
- [ ] 是否引入新的对外接口？是否有限流？

---

## 落地小动作

写代码前，把上面没勾的 checkbox 在 PR 描述里**显式列出**：要么"已确认 OK"，要么"已知问题，下个迭代解决"。**不允许默不作声地跳过**。

> 这份清单不替代代码评审，但能消除 80% 的低级问题。
